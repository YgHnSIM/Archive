01. 한눈에 보기 (예습 브리프)

핵심 테제: LangChain이나 AutoGen 같은 복잡한 프레임워크 뒤에 숨겨진 코딩 에이전트의 본질은 사실 300줄 남짓의 무한 루프(While Loop)에 불과합니다. 모델에게 시스템 프롬프트와 도구 목록(JSON Schema)을 전달하고, 모델의 도구 호출 응답을 가로채 로컬에서 실행(파일 읽기/쓰기, 셸 실행)한 뒤, 그 결과를 다시 대화 메시지에 주입하여 다음 행동을 묻는 사이클입니다.

단계작업 내용핵심 엔지니어링 고려 사항
1. 프롬프트 & 스키마작업 지시와 도구 명세(JSON Schema) 정의도구 설명문의 명확성, 모델의 함수 호출 정확도 좌우
2. 모델 호출대화 히스토리를 전달하여 LLM 응답 수신도구 호출(tool_calls) 발생 여부 분기 판정
3. 로컬 도구 디스패치명령 실행(bash), 파일 조작(read/write)샌드박스 격리, 타임아웃, 위험 명령어 필터링
4. 결과 주입 및 루프실행 stdout/stderr를 Tool 메시지로 추가 후 재호출컨텍스트 토큰 초과 방지, 반복 루프 감지

02. 에이전트의 본질: ReAct 루프의 실체

에이전트 루프의 뼈대는 ReAct (Reasoning + Acting)입니다: ① 추론(생각) → ② 행동(도구 선택 및 인자 생성) → ③ 관찰(도구 실행 결과 수신). 종료 조건은 모델이 더 이상 도구 호출을 생성하지 않고 일반 텍스트 답변을 반환하거나, 사전에 정의된 최대 반복 횟수(예: 30회)에 도달하는 것입니다.

ReAct 패턴 에이전트 루프 종료 조건 무한 루프 방지

03. 도구 호출(Tool Use)과 JSON Schema

코딩 에이전트가 갖추어야 할 4대 필수 도구는 read_file, write_file, list_dir, execute_command입니다. 도구 인자는 정형화된 JSON Schema로 선언되며, 모델은 이 스키마에 맞춰 정확한 키와 타입을 반환해야 합니다. 파싱 실패 시 모델에게 에러 메시지를 돌려주어 스스로 교정(Self-Correction)하게 유도합니다.

JSON Schema 함수 호출 (Function Calling) 자가 교정 (Self-Correction) 4대 필수 도구

04. 안전한 환경: 샌드박스와 롤백 전략

에이전트가 위험한 명령어(rm -rf / 등)를 실행하거나 네트워크 포트를 여는 것을 막기 위해 컨테이너 격리나 Linux seccomp 샌드박스를 적용합니다. 또한 잘못된 코드를 수정했을 때 원래 상태로 복원할 수 있도록 Git 기반의 워크트리 스냅샷이나 커밋 롤백 메커니즘을 내장해야 합니다.

샌드박스 격리 위험 명령어 필터링 Git 스냅샷 롤백 작업 디렉터리 한정

05. 컨텍스트 윈도우 관리와 히스토리 압축

파일 수십 개를 읽고 빌드 로그 수천 줄이 누적되면 LLM의 컨텍스트 한도를 초과합니다. 워크숍 코드는 대화 히스토리가 임계치에 도달했을 때, 오래된 도구 실행 결과(출력 로그)를 요약문으로 치환하거나 슬라이딩 윈도우 방식으로 오래된 중간 단계를 압축하여 성능 저하를 방지합니다.

컨텍스트 윈도우 임계치 대화 요약 (Summarization) 슬라이딩 윈도우 비용 최적화

복습 및 퀴즈

핵심 개념 플래시카드

카드를 누르면 숨겨진 해설이 나타납니다.

빈칸 채우기

  • 추론과 행동, 관찰을 번갈아 수행하는 에이전트 패턴을 패턴이라 한다.
  • 도구 매개변수의 형식과 설명을 규정하는 표준 명세는 이다.
  • 에이전트가 실행하는 프로세스를 호스트와 격리하는 안전 환경을 라 부른다.
  • 컴파일 에러가 발생했을 때 에이전트가 스스로 실수를 바로잡는 과정을 (Self-Correction)이라 한다.
  • 토큰 한도 초과를 막기 위해 이전 도구 실행 결과를 간추리는 기법을 컨텍스트 (요약)이라 한다.
  • 에이전트 루프의 종료 조건은 모델이 더 이상 을 요청하지 않고 답변을 낼 때이다.

5문항 퀴즈

1. 프레임워크 없는 코딩 에이전트의 핵심 아키텍처를 가장 정확히 설명한 것은?
정답: ②. 에이전트의 실체는 LLM의 함수 호출 응답을 로컬에서 실행하고 되돌려주는 단순한 루프입니다.
2. 코딩 에이전트에게 '도구 호출(Tool Use)'이 필수적인 근본 이유는?
정답: ③. LLM은 환경 격리된 언어 모델이므로 실제 디스크와 통신하기 위해 도구 호출 추상화가 필요합니다.
3. 도구 실행 시 '샌드박스 격리'가 부재할 경우 발생하는 가장 위험한 사고는?
정답: ①. 신뢰할 수 없는 모델 명령을 호스트 권한으로 직접 실행하면 파괴적 재앙이 일어납니다.
4. 에이전트 루프가 무한히 도는 '무한 루프(Infinite Loop)'를 방지하는 표준 기법은?
정답: ④. 고정된 반복 한도 카운터와 타임아웃을 설정하여 자원 낭비와 폭주를 차단합니다.
5. 도구 실행 결과로 수만 줄의 빌드 로그가 나왔을 때 에이전트 시스템이 취해야 할 조치는?
정답: ②. 컨텍스트 윈도우 폭증을 막고 핵심 디버깅 정보만 모델에 전달하기 위해 트렁케이션 및 요약이 필수입니다.
