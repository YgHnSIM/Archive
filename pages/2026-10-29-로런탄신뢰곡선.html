한눈에 보기

여섯 가지 핵심 논거

  1. 신뢰는 사다리처럼 쌓인다. 신뢰 인프라 없는 확장은 마이크로매니징을 낳는다.
  2. 1차 지렛대는 런타임 검증이다. 결과를 관측해야 언덕 오르기 루프가 완성된다.
  3. 2차 지렛대는 환경 설계다. 결정적 절차는 CLI로, 실수는 린트와 타입으로 막는다.
  4. 내부·외부 루프를 잇는다. 사람은 맥락 전달자 병목에서 빠진다.
  5. 리뷰는 사후 표본 감사로. 고칠 대상은 개별 PR이 아니라 환경이다.
  6. 한계선은 검증 가능성이다. 일방통행 문에는 사람의 게이트키핑이 남는다.

발표 "How I shipped 2,500 PRs last month to production"은 X에서 약 300만 회 조회되었다. 확인 필요 PR 수는 영상 제목의 1,000개, 대담 중의 2,000개와 2,500개가 섞여 나온다. 확인 필요 진행자는 맷 포콕(Matt Pocock)으로 추정된다. 확인 필요

1

고기 프록시의 자각

마이크로매니징에서 탈출하기

Meta React 팀을 떠나 한 달을 쉬던 로런 탄은 사이드 프로젝트에서 에이전트 하나를 붙잡고 몇 시간씩 개입했다. 그래서 자신이 일하는 방식을 스킬로 추출해 에이전트가 "나처럼" 일하게 가르쳤다. 이 스킬과 brain 디렉터리가 스킬 묶음 pstack(자막 'PAC')의 바탕이 되었다. 확인 필요

Cursor 합류 직후 4월 초, 에이전트 창의 성능 저하를 디버깅하며 힙 스냅샷과 플레임 그래프를 손으로 보던 그는 자신이 에이전트와 Chrome DevTools 사이의 "고기 프록시"라는 것을 깨달았다.

그림으로 보기: 고기 프록시

최신 프런티어 모델도 지름길을 택하기 쉽다. 그래서 그의 스킬 상당수는 "쉬운 일을 올바른 일로 만드는 것"을 겨냥한다.

고밀도 도메인 언어

병목은 의도 표현으로 옮겨 간다

모델이 좋아질수록(그는 "Opus 5.5"를 좋아한다고 했다 확인 필요) 병목은 사람이 의도를 얼마나 명확하게 표현하느냐로 옮겨 간다. 프로그래밍을 조금 아는 의사나 변호사가 유리한 이유다.

진행자는 에이전트가 TDD나 'grilling' 같은 핵심 단어를 잡으면 사고 과정 내내 반복한다고 관찰했다. 로런 탄이 가장 싫어하는 것은 동어반복 테스트다. 'tautology' 한 단어에 많은 의도가 압축되어 있다.

미슐랭 키친

소프트웨어 공장이 아니다

로런 탄은 '소프트웨어 공장' 비유가 규모는 설명해도 품질과 장인정신을 담지 못한다며 미슐랭 키친을 제안한다. 총괄 셰프는 프라이팬을 잡지 않고 동선과 재료와 워크플로를 설계한다.

런타임 검증

루프를 완성하는 단 하나의 스킬

로런 탄은 가장 중요한 단 하나의 스킬이 검증이라고 단언한다. Cursor에서 처음 만든 스킬도 검증 스킬이었다. 검증은 에이전트에게 손과 눈을 달아 코드를 실행하고, 사용자처럼 조작하고, 트레이스와 스냅샷을 뜨게 한다.

그림으로 보기: 열린 루프와 닫힌 루프
그림으로 보기: 언덕 오르기

그는 안드레이 카파시가 공개한 auto research에도 이 생각이 담겨 있다고 말한다. 확인 필요 지금은 Cursor(자막상 "SpaceX AI")의 모든 앱에 자동으로 유지되는 검증 스킬이 있다. 확인 필요

환경 설계와 Dune

나쁜 코드를 불가능하게

엔지니어의 새 일은 환경에 시간을 쓰는 것이다. 신뢰가 낮으면 감시에 매달려 환경을 개선할 시간이 없다. 핵심 철학은 TypeScript의 타입 좁히기처럼 코드베이스의 유효 상태 공간을 좁히는 것이다.

그는 사내 Electron 앱용 비공개 프레임워크 Dune("Electron 앱을 위한 사내 Next.js")을 만들고 있다. 확인 필요 계기는 Cursor 에이전트 창(agents window) 초기 버전이 1만 줄 이상의 갓 파일 8개쯤으로 되어 있었다는 점이다. 확인 필요

그림으로 보기: Dune

에이전트가 실수하면 "다음부터 이러지 마"라고 하지 말고, 그 실수를 린트나 컴파일러 제약으로 불가능하게 만든다. 진행자의 정리처럼, 규칙을 환경에 두면 에이전트가 필요한 순간에 부딪혀 튕겨 나온다.

이중 루프와 코디네이터

대량 배포의 엔진

대량 머지의 전제는 견고한 환경이다. 고든 램지가 주방 하나를 완벽히 세팅해야 2호점을 열 수 있듯이. 그는 프로젝트 세션을 하나의 식당으로 보고 헬리콥터처럼 그 사이를 오간다.

내부 루프의 의도 스냅샷은 빠르게 낡는다. 외부 루프에는 Slack, Linear, X, 이메일의 맥락이 흐른다. 그는 "어디서 내가 병목인가?"를 묻고, 거창한 '컴퍼니 브레인' 대신 실제 데이터 소스를 에이전트에 직접 연결하라고 조언한다. 외부 루프의 감시자 역할은 Cursor 에이전트 확인 필요가 수행한다.

그림으로 보기: 이중 루프 파이프라인

30개 이슈가 한꺼번에 오면 코디네이터가 연관성을 분석해 작업을 나눈다. 이슈마다 에이전트를 띄우면 공통 원인을 놓치기 때문이다. 넷플릭스 관리자들의 원칙 "통제가 아닌 맥락(Context, not Control)"이 에이전트에도 들어맞는다.

다크 팩토리

사전 차단에서 사후 표본 감사로

그는 "에이전트가 사람 리뷰 없이 머지하려면?"에서 거꾸로 설계했다. 모든 접시를 맛볼 수는 없으니 표본 검사로 품질을 보고, 아침에 커밋 기록을 리뷰한다.

그림으로 보기: 리뷰의 역전

10개 이상의 전담 에이전트가 24시간 일하고 확인 필요, pstack의 풀 오토파일럿 모드에서는 PR마다 여러 검증 에이전트(예로 10개)가 퍼징한다. 확인 필요 처음 켠 밤은 무서웠지만 지금은 잠을 더 잘 잔다.

그림으로 보기: 풀 오토파일럿

진행자는 이를 코드의 존재를 잊는 '바이브 코딩'과 구별해, 여기서는 코드와 환경이 핵심이고 "차단 대신 표본 검사"가 중요하다고 정리했다.

되돌릴 수 없는 일방통행 문은? 로런 탄은 결국 에이전트에게서 얻는 검증의 질로 돌아온다고 답하고, 답은 자신도 없다고 인정한다. 증명과 프로그래밍을 결합한 언어의 예로 Bend를 든다. 확인 필요

대화 기록과 스킬

프로세스를 말로 바꾸기

"스킬이란 말로 바꾼 프로세스다." 진행자의 스킬(grill me, wayfinder)과 pstack은 경쟁이 아니라 보완 관계다. 확인 필요 셰프가 자기 칼 가방을 챙기듯, 엔지니어는 자기 도구를 벼려야 한다.

스킬의 원재료는 과거 대화 기록이다. 에이전트에게 이전 대화를 분석해 내가 끼어든 지점을 찾게 하라는 것이다. recall 스킬은 긴 디버깅 뒤 새 채팅에 이전 채팅의 좋은 맥락을 가져오고 싶었던 데서 나왔다.

그림으로 보기: 대화 기록 채굴
그림으로 보기: 스킬의 미래

엔지니어는 에이전트가 실수를 저지르고 싶어도 저지를 수 없는 물리 법칙을 설계하는 주방의 건축가다.
