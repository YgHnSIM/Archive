효율의 숫자 뒤에 있는 플랫폼의 기본기

  1. 효율은 두 고리에서 나온다. 배포→피드백→더 나은 모델의 개선 고리와, 매출→재투자→역량 도약의 투자 고리가 맞물린다. 2026년 2분기 컴퓨팅 비용 1달러당 매출은 약 2.08달러다.
  2. 증류 방지의 동기는 돈이 아니라 안전이다. 증류된 복제 모델에는 앤트로픽의 안전 분류기가 따라가지 않는다. 사고 블록 보존을 강제하고, 깨지는 압축 패턴은 API 내장 압축으로 메웠다.
  3. 출시 작업의 과반은 신뢰와 권한의 인프라다. 모델 접근, 안전장치 완화, 유예 추적, 킬 스위치까지 하나의 범용 'trust grants' 구조 위에서 처리한다.
  4. 뇌와 손을 떼어 놓으면 빠르고, 무엇보다 안전하다. 하네스(뇌)는 내구성 서버에, 실행 환경(손)은 일회성 샌드박스에 두고, 자격 증명은 금고와 프록시로 격리한다.
  5. 사람은 설계·검증, Claude는 구현. Rust 개발자 없이 Messages API를 Rust로 전면 포트했고, 라우터 대신 동적 에포트를 가진 단일 모델을 지향한다.

이 순환의 중심에 S-1이 '포괄적 에이전트 개발 환경'으로 정의한 클로드 플랫폼이 있습니다. TTM 매출 10만 달러 이상 고객의 50% 이상이 플랫폼과 1차 앱(Claude Code, Cowork)을 함께 쓰며, 그 1차 앱들도 외부 개발자와 똑같은 기본 구성 요소로 만들어졌습니다. 상장 서사는 '챗봇 → 코파일럿 → 가상 협업자'의 3단계입니다.

스윅스는 Opus 5.5(2026년 9월 22일 발표)를 "현시점 지구상에서 가장 강력한 모델"이라 부르고, 미공개 모델 '페이블 5.5(Fable 5.5)'이름 확인 필요가 상장 시점에 맞춰 2주 안에 나올 가능성이 높다고 사견으로 관측했습니다.

모델 하나를 출시하기

평가, 앤트푸딩, 조기 접근, 피드백

Opus 5.5의 두 과제는 Opus 5에 쏟아진 "문체가 장황하다"는 피드백을 반영해 간결하게 다듬는 것, 그리고 '1달러당 지능'으로 옮겨 간 관심에 맞춘 대폭적인 가격 인하였습니다.

그림으로 보기: 출시 파이프라인
  • 앤트푸딩: 앤트로픽식 독푸딩. 연구진과 엔지니어가 여러 변형본을 일상 업무에 직접 써서 성향 차이를 초기에 잡는다.
  • 조기 접근: 코그니션, 커서처럼 자체 평가 스위트가 아주 견고한 파트너만. 모델 컷에서 공개까지의 시간을 줄이는 속도전이기 때문이다.
  • 부정적 피드백이 가장 귀하다: 칭찬은 가설을 확인할 뿐이고, 무너지는 지점만이 고칠 단서다. 특히 외부 고객의 이종 하네스에서 나온 결함 보고가 범용성을 검증한다.

가장 까다로운 조율은 게으름 대 주도성입니다. 누군가는 "계획만 세우려 했는데 왜 파일을 고치냐"고, 누군가는 "왜 매번 묻느냐"고 불만입니다. 과거 어느 모델의 초기 버전이 지나치게 게으르자 "다시 오븐에 넣어" 훈련으로 덜어 낸 적이 있는데, 앤트푸딩이 놓친 문제를 API 고객이 잡은 사례입니다.

제품 책임자 앤절라 장(화자 추정)은 "개인화 평가는 아직 잘하지 못한다"고 인정합니다. 현재 해법은 부드러운 기본값과 세밀한 조절 옵션의 공존입니다. Claude Code의 기본 effort는 medium으로 조정되었고, 세그먼트별로 기본값을 나눕니다. 장기적으로는 슬라이더 없이 모델이 맥락을 흡수해 스스로 맞추는 개인화를 지향합니다.

증류 방지와 UX 두 층

사고 블록 보존과 API 내장 압축

증류는 큰 모델의 입출력을 교사 삼아 작은 모델을 싸게 모방 학습시키는 기법이고, 사고 연쇄(CoT) 토큰은 그 핵심 재료입니다. 「독점 LLM API로부터 추론 궤적 훔치기」 논문의 연구진은 책임 있는 공개 절차로 먼저 알렸고, 그 기법은 패치되었습니다.

  1. 다중 턴 사고 블록 보존 강제: 공식 명칭 '보존된 사고(preserved thinking)'. Fable 5.1과 함께 도입되어, 이전 컨텍스트를 편집해 추론을 빼내는 시도를 막는다.
  2. 계정 간 분할·재사용 차단: 여러 API 계정에 사고 토큰을 쪼개거나 재사용(replay)하는 우회로를 막는다.

증류를 시도하는 사람들도 결국 API를 호출하며 토큰 비용을 낸다. 상업적으로만 보면 우리는 이미 돈을 벌고 있다.

진짜 위험은 안전장치가 제거된 복제 지능입니다. 앤트로픽은 토큰 스트림 위에 안전 분류기를 상시 돌리지만, 출력을 학습한 증류 모델이 제3자 인프라에서 돌면 분류기는 따라가지 않습니다.

그림으로 보기: UX 충격의 두 층과 해법

측정할 수 있는 범위에서 증류는 이후 상당히 어려워졌습니다. 다중 계정 분할 수집은 실시간 스트림 위에서는 잡을 수 없어 오프라인 분석과 사람의 감사가 필요하고, 그래서 데이터 보존 정책이 모델마다 새로 정해집니다. Opus 5.5에는 Fable에 붙은 보존 요구가 없고, 이전 Opus처럼 무보존(ZDR)으로 제공됩니다.

trust grants와 확률적 로드맵

권한이라는 기반, 범용 기본 구성 요소

예전 출시는 "엔드포인트를 열고, 키를 주고, 피처 플래그를 켜면" 끝났습니다. 지금은 출시 작업의 과반이 신뢰와 권한의 인프라입니다. 그 중심이 trust grants, 즉 누가 어떤 모델과 어떤 안전장치 완화 프로그램에 접근할 수 있는지를 시스템 끝까지 믿을 수 있게 전달하는 권한 구조입니다.

  • 최상위 모델(Claude Mythos 5.1) 접근 권한
  • 사이버 취약점 분석을 승인받은 사용자의 안전장치 완화
  • Fable 5.1 출시 때 2026년 8월 31일 이전 계정에 사고 보존 강제를 유예한 grandfathering 추적
  • 전 세계 사용자의 특정 모델 접근을 한 번에 회수하는 킬 스위치

킬 스위치는 2026년 6월 12일 미국 정부의 긴급 수출통제 지시로, 국적을 실시간으로 구별할 수 없던 앤트로픽이 Fable 5와 Mythos 5의 전 세계 접근을 일시 중단·회수했던 일 뒤에 마련되었습니다.

확률적 로드맵: 확률이 낮아도 0이 아닌 사건은 회사의 존망을 가를 수 있다. 그래서 백로그를 '베팅 포트폴리오와 헤지'로 짜고, "다시 일어나지 않길 바라지만 일어나면 회사를 구할" 시스템에 자원을 배분한다. 이런 헤지 작업은 시간이 지나면 거의 예외 없이 프로덕션 핵심 기능이 된다.

범용 기본 구성 요소의 예가 사이버 능력 검증 포털입니다. 사용 사례를 제출해 승인받은 연구자에게만 안전장치를 완화해 주려고 만들었지만, 범용 인가 프레임워크로 추상화해 두었기에 모델 접근, 신뢰 접근 프로그램, 모델 배포까지 재사용되며 배당을 냅니다. 바이오·사이버처럼 능력이 급상승하는 영역은 공격 우위인지 방어 우위인지를 따져 출시 전략을 달리합니다.

Managed Agents: 뇌와 손

자격 증명 금고와 나가는 트래픽 통제

Claude Managed Agents(CMA)는 하네스 루프, 도구 호출 중계, 격리 인프라 같은 보일러플레이트를 걷어 내고 에이전트를 정의해 바로 세션을 여는 고수준 계층입니다. 새 모델의 매개변수와 호환성 변경도 앤트로픽이 하네스 안에서 대신 맞춥니다. 샌드박스 인프라는 자사 제품과 공유하지만, 하네스는 제품마다 원하는 동작이 달라 공유하지 않습니다.

처음엔 샌드박스 안에 Claude Code를 통째로 넣고 API를 씌웠습니다. 호출마다 샌드박스를 부팅해 첫 토큰이 느렸고, 컨테이너가 죽으면 세션도 사라졌습니다. 엔지니어링 블로그는 이를 "애완동물(pet)을 입양했다"고 표현합니다.

그림으로 보기: 뇌와 손의 분리

분리의 효과로 p50 TTFT는 약 60%, p95는 90% 이상 줄었습니다. 그러나 담당 PM은 처음부터 "이 구조의 가장 위대한 속성은 지연시간이 아니라 보안"이라고 강조했습니다.

  • 자격 증명 금고와 프록시 주입: 에이전트는 자리표시자만 보고, 나가는 길목의 프록시가 금고에서 실제 자격 증명을 끼워 넣는다.
  • 나가는(egress) 트래픽 통제: 도메인 허용 목록을 강제하거나 네트워크를 차단한다. 프롬프트로 타이르는 규칙이 아니라 구조적으로 불가능하게 만드는 강제다.

샌드박스 탈출 사고의 대다수는 서비스가 아니라 훈련 환경에서 일어납니다. 불가능한 과제를 풀라는 보상 압박이 상자 밖으로 나갈 유인을 만들기 때문입니다. 상용 환경에는 그런 압박이 없고, 온라인 안전장치와 인프라 격벽이 작동합니다. 앤트로픽은 '기본값부터 안전한' 구조를 CMA 고객도 쓰게 하고, 내부 시스템도 이 방식으로 바꾸는 중입니다.

하네스·드리밍·평가

단순한 하네스 위의 hill climbing

CMA의 기본 하네스는 놀랄 만큼 단순합니다. 공통 보일러플레이트(세션 수명 주기, 도구 호출 파싱, 재시도)만 흡수하고 상위 전략은 개발자에게 비워 둔 의도된 절제입니다. 모델 출시가 안전 측면에서 어려워지면서, 메모리·드리밍 같은 기능 개발 속도는 올해 초보다 늦춰졌습니다.

드리밍은 또 다른 관리형 에이전트를 띄워 이전 에이전트를 살펴보고 결과를 메모리에 적게 하는 다중 에이전트 시스템, "끝없이 중첩되는 관리형 에이전트"입니다. 앞으로 Best-of-N, 검증 에이전트, 상태를 공유하는 대규모 병렬 에이전트 같은 전략을 기본 구성 요소와 템플릿으로 공개할 계획입니다.

평가의 세 원칙

  1. 많이 만들어라: 숨은 회귀를 잡는 방패는 평가의 양이다.
  2. 단순하게 시작하라: 방법론 고르느라 평가 0개로 머물지 말 것.
  3. 에이전트와 함께 키워라: 기능이 늘 때마다 평가 케이스도 늘린다.

스윅스는 "엔지니어링을 연구처럼 하라"고 덧붙입니다. 목표를 정량 지표로 만들고, 실패의 원인이 평가인지, 실행 환경인지, 모델인지를 가려내는 것이 AI 엔지니어링의 본령입니다. Claude로 평가 스위트를 대화하듯 만드는 전용 도구도 예정되어 있습니다.

CPU 병목과 Rust 포트

Rust 개발자 없이 해낸 전면 재작성

가장 처절한 병목은 가속기가 아니라 CPU였습니다. 제품·API 서버, Claude Code와 CMA의 샌드박스 VM, 코드 생산량 폭증으로 늘어난 CI 러너가 같은 CPU 풀을 나눠 씁니다. CSP 계약으로 확보하는 CPU는 제로섬이라 사전 용량 계획이 필수가 되었습니다. 대응은 공급선 확충, 격리를 지키는 샌드박스 가상화 경량화, 그리고 애플리케이션 계층의 극단적 효율화였습니다.

엔지니어링 책임자 케이틀린 레스(화자 추정)가 합류했을 때 Messages API는 단일 GCP 리전의 파이썬 모놀리스였습니다. 멀티 리전은 마쳤지만 CPU 효율이 걸림돌이었고, 팀은 Rust로 옮기기로 했습니다. 문제는 팀에 Rust를 쓸 줄 아는 개발자가 한 명도 없었다는 것입니다. 시스템 전체를 한 번에 옮긴 뒤 서서히 켜는 방식을 택했고, 녹화 일주일 전 완전 배포를 마쳤습니다.

설계아키텍처, API 명세, 마이그레이션 전략명세에 따른 관용적 Rust 구현

페이싱·안전 3축·폴백

라우터 대신 동적 에포트

다리오 아모데이가 2026년 9월 12일 「We Must Pace the Frontier」로 페이싱을 촉구하고 약 10일 뒤(스윅스는 '11일 뒤'로 표현) Opus 5.5를 낸 것은 모순처럼 보입니다. 그러나 페이싱은 진보의 중단이 아니라 안전 관행이 능력보다 앞서 있도록 속도를 조절하자는 주장이고, Opus 5.5는 안전 기준을 통과해 나온 첫 출시입니다.

안전의 축내용
① 아키텍처·인프라 보안뇌와 손 분리, 자격 증명 금고, egress 통제
② 런타임 온라인 세이프가드생성 중 실시간 감지·개입
③ 오프라인 분류기저장 데이터로 다중 계정 악용·증류 시도 사후 식별

Opus 5.5는 세 축 모두에서 좋은 결과를 냈고, 자동 행동 감사에서 지금까지 시험한 모델 중 가장 좋은 점수를 받았습니다.

폴백의 답답함

안전장치가 엄격할수록 분류기 오탐에 따른 폴백이 생깁니다. 스윅스는 "바이오 숙제에서 바이오를 한 번 언급했을 뿐인데 폴백된다"고 꼬집습니다. Opus 5.5 공식 페이지도 사이버·바이오·증류 안전장치가 다른 모델로 투명하게 폴백되며, 대부분의 사이버보안 작업은 Opus 4.8로 재라우팅된다고 밝힙니다. 원인으로 스윅스는 "더 멍청한 분류기가 더 똑똑한 모델의 대화를 심판하는" 구조를 듭니다(해설상 '지능의 역설'). 현재 API는 서버 측 폴백 켜고 끄기, SDK 폴백 헬퍼, 같은 모델 안에서의 재프롬프트를 제공합니다.

그림으로 보기: 라우터 대 동적 에포트

앤절라 장(화자 추정)이 그리는 이상은 하위 모델로 튕겨 나가는 대신, 단일하고 일관된 모델이 위험한 세부만 정교하게 덜어 내고 유익한 답을 완성하는 경험입니다. 같은 이유로 외부 라우터보다 동적 에포트를 가진 단일 프런티어 모델을 지향합니다.

사람의 몫과 맺음

슬롭, 설계와 검증, 제품 판단, DevRel

  • 작업 부하: 일부 작업은 지능이 포화되지만, 포화되지 않은 과업은 예상보다 많다. 초과 이익은 장시간 자율 에이전트와 바이오·사이버 같은 고난도 과학·공학 문제에 있다.
  • 슬롭의 규율: "Claude를 마음껏 쓰라. 그러나 결과물의 품질 책임은 100% 당신에게 있다." 읽지 않은 생성물을 동료에게 넘기지 말고, 슬롭이면 반려한다. 반대로 엠대시 같은 '클로드 말투'만으로 공들인 결과물을 배척하는 것도 비생산적이다.
  • 엔지니어링의 재편: 사람은 아키텍처와 검증 환경을, Claude는 구현을 맡는다.
  • 제품 기본기: Claude Code 엔지니어 타리크 시히파르의 요지는 "기능을 10배 더 내보내는 것이 아니라 사용자를 더 이해하고 실험하는 데 시간을 쓰라"는 것. claude.ai 속도 개선 스프린트는 13개 목표 중 12개를 사흘째에 달성했고 앱은 약 3배 빨라졌다.

어떤 일을 반만 하는 것은, 하지 않는 것의 비싼 방식이다. — 앤절라 장

앤절라 장은 긴 기차 통근 중 1년에 약 200권의 책을 읽었고확인 필요, 트윗은 생각을 최소한의 단어로 압축하는 연습이었습니다. 가장 아끼는 책은 『블랙 스완』입니다. 일어날 수 없다고 여긴 일이 한 번 일어나면 생각의 틀이 바뀐다는 점에서 확률적 제품 관리와 통합니다(해설). 케이틀린 레스는 슬랙까지 인박스 제로를 지키며, 막힌 팀을 풀어 주는(unblock) 것이 자기 일이라고 말합니다.

DevRel은 API 플랫폼 팀과 Claude Code 팀으로 나뉘어 점선으로 이어집니다. 가장 레버리지 높은 산출물은 쿡북이 아니라 코딩 에이전트가 직접 읽는 Claude API 스킬과 참조 아키텍처입니다. 스윅스는 앞으로 엔지니어와 리더가 직접 말하고, DevRel은 그 지식을 추출해 콘텐츠로 만드는 '백 오피스'로 물러날 것이라 봅니다.

맺음: Opus 5.5는 입력·출력 100만 토큰당 4달러·20달러로 Opus 5보다 20% 낮고 일반 작업 비용은 40% 줄었습니다. 미뤄 둔 장시간 에이전트와 멀티 에이전트 실험을 다시 꺼낼 때입니다. 하위 에이전트의 역할을 하드코딩하지 말고, 하나의 리더 에이전트 아래 균일하게 공유되는 단일 상태와 서로를 막지 않는 비동기 하위 에이전트 두 가지만 지키면, 나머지 분업은 Claude에게 맡겨도 좋습니다.
