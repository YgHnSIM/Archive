01. 한눈에 보기 (예습 브리프)

핵심 테제: 파이썬에서 괄호 ()를 붙여 호출할 수 있는 모든 것(함수, 클래스, 메서드, __call__ 구현체)은 C 수준에서 해당 객체의 타입에 tp_call 또는 현대적인 vectorcall 함수 포인터가 등록된 호출 가능 객체(Callable)입니다. CPython은 전통적인 임시 튜플·딕셔너리 생성 오버헤드를 없애기 위해 C 배열 포인터로 인자를 직접 전달하는 vectorcall 프로토콜(PEP 590)을 도입하여 함수 호출 속도를 비약적으로 향상시켰습니다.

구분전통적 호출 방식 (tp_call)현대적 고속 호출 방식 (vectorcall, PEP 590)
인자 전달 형태위치 인자 PyTuple + 키워드 인자 PyDictC 포인터 배열 PyObject *const *args
메모리 할당 오버헤드호출할 때마다 임시 튜플·딕셔너리 힙 할당 발생스택의 C 배열을 그대로 넘겨 힙 할당 제로(0)
바이트코드 처리CALL_FUNCTION 복잡한 인자 언패킹특화 바이트코드 CALL 직접 디스패치
적용 대상레거시 C 확장 모듈 및 구형 타입내장 함수, 파이썬 함수, 메서드 래퍼 전반

02. 호출 가능 객체의 조건: tp_call 슬롯

파이썬 객체 x 뒤에 괄호를 붙여 x(a, b)를 실행할 수 있는 이유는 x->ob_type->tp_call 슬롯에 C 함수 포인터가 채워져 있기 때문입니다. 만약 사용자 정의 클래스에 def __call__(self):를 선언하면, CPython은 해당 클래스의 tp_call 슬롯에 slot_tp_call 래퍼 함수를 연결하여 인스턴스를 호출 가능 객체로 만듭니다.

tp_call 슬롯 __call__ 특수 메서드 PyCallable_Check 호출 가능 여부 판정

03. 호출 오버헤드의 주범과 vectorcall 혁신

파이썬 3.7 이전에는 func(1, 2)를 호출하기만 해도 (1, 2) 튜플을 힙에 만들고 해제하는 불필요한 GC 부하가 있었습니다. vectorcall (PEP 590)은 호출 규약을 개혁하여 스택 프레임에 이미 존재하는 인자 포인터 배열을 그대로 함수에 넘김으로써 임시 객체 생성을 완전히 제거했습니다.

PEP 590 vectorcall 프로토콜 힙 할당 제거 임시 튜플 오버헤드

04. 바이트코드 수준의 호출: CALL에서 프레임 진입까지

파이썬 컴파일러는 호출 표현식을 만나면 인자들을 스택에 푸시한 뒤 CALL 바이트코드를 내보냅니다. CPython의 거대한 루프인 _PyEval_EvalFrameDefault 함수 안에서 CALL은 타깃 객체의 vectorcall 오프셋을 확인하여 C 함수면 직접 C 포인터를 점프하고, 파이썬 함수면 새 인터프리터 프레임(_PyInterpreterFrame)을 스택에 푸시합니다.

CALL 바이트코드 _PyEval_EvalFrameDefault 인터프리터 스택 C 콜스택 vs 파이썬 프레임

05. 프레임 스택과 제너레이터의 일시 중단

파이썬 3.11부터 도입된 가벼운 프레임 구조는 C 콜스택과 파이썬 논리 프레임을 깔끔하게 분리했습니다. 함수가 yield를 만나면 프레임의 명령어 포인터(IP)와 로컬 변수 상태를 힙에 보존한 채 C 루프를 빠져나오고, next()로 재호출되면 이전 IP 지점부터 실행을 즉시 재개합니다.

_PyInterpreterFrame 제너레이터 (yield) 명령어 포인터 보존 파이썬 3.11 프레임 경량화

빈칸 채우기

  • 객체의 호출 가능 여부를 결정하는 타입 슬롯은 이다.
  • 임시 튜플 없이 C 포인터 배열로 인자를 넘기는 고속 호출 프로토콜은 (PEP 590)이다.
  • CPython 바이트코드를 순회하며 실행하는 핵심 루프 함수는 이다.
  • 클래스 인스턴스를 호출 가능하게 만들려면 메서드를 구현해야 한다.
  • 파이썬 함수 실행 시 로컬 변수와 스택을 담는 메모리 단위를 인터프리터 (Frame)이라 부른다.
  • 제너레이터 함수는 키워드를 만나면 프레임 상태를 보존한 채 일시 중단된다.

5문항 퀴즈

1. CPython에서 어떤 객체를 `obj()` 형태로 호출할 수 있는지 판별하는 기준은?
정답: ②. CPython 런타임은 타입 슬롯의 `tp_call` 포인터 유무로 호출 가능성을 판정합니다.
2. PEP 590 'vectorcall' 도입으로 얻게 된 가장 큰 성능상 이점은?
정답: ③. C 배열 포인터를 직접 전달하여 불필요한 임시 객체 생성 오버헤드를 없앴습니다.
3. CPython 바이트코드 평가 루프(`_PyEval_EvalFrameDefault`)의 실제 구현 구조는?
정답: ①. 인터프리터의 기본 구조는 바이트코드를 하나씩 꺼내 분기하는 거대한 C 루프입니다.
4. 사용자 정의 클래스 인스턴스를 함수처럼 `instance(1, 2)`로 호출하려면 구현해야 하는 매직 메서드는?
정답: ④. `__call__` 메서드를 구현하면 클래스의 `tp_call` 슬롯이 채워져 인스턴스 호출이 가능해집니다.
5. 제너레이터 함수가 `yield`를 만났을 때 CPython 인터프리터 내부에서 일어나는 일은?
정답: ②. 프레임의 실행 상태를 그대로 힙에 남겨두고 복귀하므로 이후 next()로 재개할 수 있습니다.
