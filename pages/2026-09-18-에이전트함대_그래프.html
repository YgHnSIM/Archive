에이전트 함대 그래프 아키텍처 핵심 요약: 사슬에서 그래프로

핵심 명제: 에이전트를 똑똑하게 만드는 비결은 긴 단일 프롬프트가 아니라, 서로 의존하지 않는 작업의 가짜 대기를 지우고 유향 비순환 그래프(DAG)로 병렬 실행하는 데 있습니다. "조율은 코드(토큰 0), 판단만 모델"이 에이전트 함대의 설계 철학입니다.

1. 사슬(Chain)에서 그래프(Graph)로의 전환

초기 멀티스텝 LLM 파이프라인은 직렬 파이프라인 형태(A → B → C → D)로 구축되었습니다. 그러나 각 단계가 이전 단계의 모든 출력을 필요로 하지 않음에도 직렬 대기함에 따라 치명적인 병목이 발생했습니다.

직렬 사슬 (Sequential Chain)

  • 모든 단계가 차례대로 대기 (가짜 대기 시간 누적)
  • 앞선 단계의 토큰이 뒤로 갈수록 누적되어 컨텍스트 오염
  • 한 단계 오류 시 전체 파이프라인 정지

유향 비순환 그래프 (DAG)

  • 독립된 노드는 즉시 병렬(팬아웃) 실행
  • 진짜 데이터 의존성이 있는 간선(Edge)에서만 대기·합류
  • 소형 모델과 대형 모델의 적재적소 티어링 분배

2. 에이전트 함대 운영의 3대 핵심 원칙

  • 가짜 화살표 제거: 데이터 흐름 관점에서 B가 A의 결과를 직접 읽지 않는다면 두 노드 사이의 화살표를 지우고 병렬로 분기합니다.
  • 결정론적 조율(Orchestration): 어떤 노드를 먼저 실행하고 합류할지 결정하는 흐름 제어는 LLM이 아닌 파이썬/타입스크립트 코드가 담당하여 토큰 비용을 0으로 유지합니다.
  • 모델 티어링(Tiering): 파일 탐색이나 포맷 변환 등 단순 작업에는 소형/고속 모델(Flash, Mini)을 배치하고, 최종 합성 및 아키텍처 판단 노드에만 플래그십 추론 모델(Pro, Opus)을 할당합니다.

📚 예습 가이드 (Pre-reading Guide)

Pages 심화 본문을 읽기 전, 아래 3가지 질문을 마음에 품고 아키텍처를 점검해 보세요.

  1. 현재 작성 중인 에이전트 워크플로에서 이전 단계 출력을 전혀 쓰지 않으면서 습관적으로 직렬 대기 중인 단계는 어디인가?
  2. 전체 파이프라인의 분기 및 예외 처리를 LLM 자연어 프롬프트에 맡기고 있는가, 아니면 호스트 코드의 명시적 제어 흐름으로 감싸고 있는가?
  3. 모든 하위 에이전트에게 비싼 최고 성능 모델을 낭비하고 있지 않은가?

💡 핵심 문답 5선 (Self-Review QA)

Q1. 왜 멀티 에이전트 시스템을 '단순히 사람 여러 명 고용하기'로 비유하면 실패합니까?

사람 여러 명이 자유롭게 회의를 시작하면 발언권 조율과 컨텍스트 중복 전달 비용이 기하급수적으로 폭증합니다. 에이전트 시스템 역시 제어 없는 LLM 간 자유 대화는 무한 루프와 컨텍스트 표류(drift)를 유발하므로, 명확한 입력-출력 계약을 가진 정적 그래프 노드로 통제되어야 합니다.

Q2. '가짜 화살표(Fake Arrow)'란 구체적으로 무엇을 뜻합니까?

A 작업의 결과물이 B 작업의 입력으로 실질적으로 참조되지 않는데도 단순히 코드 순서상 await A(); await B();로 묶여 있어 발생하는 불필요한 직렬 의존성입니다.

Q3. '조율은 코드(토큰 0), 판단만 모델'이라는 격언의 실무적 이점은 무엇입니까?

누가 다음 턴에 발언할지, 루프를 종료할 조건인지 등 제어 흐름(Control Flow)을 LLM에 질의하지 않고 호스트 런타임 조건문으로 확정함으로써 추론 지연 시간과 토큰 비용을 0으로 만들고 동작의 재현성을 100% 보장합니다.

Q4. 팬아웃(Fan-out) 후 집계(Fan-in) 단계에서 발생할 수 있는 주요 장애 요소는 무엇입니까?

병렬 실행 중 특정 하위 노드의 타임아웃, 포맷 불일치 반환, 또는 Hallucination입니다. 따라서 집계 노드 이전에 유효성 검증(Schema Validation) 필터를 반드시 통과하도록 그래프를 설계해야 합니다.

Q5. 모델 티어링(Model Tiering)을 도입할 때의 설계 기준은 무엇입니까?

작업의 복잡성과 실패 비용입니다. 단순 정보 수집·정규표현식 파싱·JSON 변환은 작고 빠른 티어의 모델을 사용하고, 기획·논리적 반박·최종 합성에는 고성능 추론 티어 모델을 지정합니다.
