AI 점수는 왜 같은 모델인데도 갈릴까: 하네스 패턴과 상태 연속성 핵심 요약

핵심 명제: AI 벤치마크 점수는 모델 단독의 '순수 지능'이 아니라, 모델을 둘러싼 '실행 환경(하네스)'과의 합작품입니다. GPT-6 Astra가 표준 하네스에서 62.7%, 프로바이더 어댑터에서 99.9%를 기록한 것은 런타임 상태 관리와 도구 연결의 중요성을 증명합니다.

1. 같은 엔진, 극단적으로 갈린 점수

복잡한 다단계 추론과 과제 해결을 평가하는 ARC-AGI-3 벤치마크에서, 동일한 가중치(Weights)의 GPT-6 Astra 모델이 실행 환경에 따라 극단적인 점수 격차를 보였습니다.

구분 표준 하네스 (Standard Harness) Provider Adapter (제품형 환경)
ARC-AGI-3 점수 62.7% 99.9%
상태(기억) 관리 매 턴 독립 호출 또는 최소 컨텍스트 실패 궤적 보존, 중간 추론 상태 누적
도구 상호작용 단순 텍스트 입출력 프로토콜 동적 코드 실행, 스크래치패드 메모리 주입
비유 벌거벗은 자동차 엔진 테스트 운전석, 내비게이션, 오토파일럿이 장착된 완성차

2. 런타임 하네스(Harness)의 3대 핵심 역할

  • 기억(상태) 연속성 보장: 에이전트가 이전 단계에서 시도했다가 실패한 코드나 추론 경로를 기억하여 무한 루프나 동일 오류 반복을 방지합니다.
  • 도구 및 샌드박스 중계: 파일 읽기/쓰기, 컴파일러 호출, 웹 검색 등의 결과를 LLM이 가장 해석하기 쉬운 구조적 포맷으로 정제하여 전달합니다.
  • 번들 vs 오픈 선택의 기로: 벤더가 제공하는 완성형 번들 어댑터는 빠른 도입과 높은 초기 성능을 보장하지만 벤더 종속(Lock-in)을 초래합니다. 반면 자체 오픈 하네스는 엔지니어링 비용이 들지만 장기적인 통제권과 모델 교체 유연성을 확보해 줍니다.

본격적인 시스템 구축 전, 우리 팀의 AI 도입 전략에 대해 아래 질문을 던져보세요.

  2. 우리의 프롬프트 엔지니어링 노력이 실은 런타임 하네스가 담당해야 할 '상태 관리 부재'를 땜질하고 있는 것은 아닌가?
  3. 특정 모델 공급자의 독점 어댑터에 지나치게 의존하여 추후 다른 오픈소스나 경쟁 모델로의 전환 비용이 너무 높아지지 않았는가?

💡 핵심 문답 5선 (Self-Review QA)

Q1. AI 모델에서 '하네스(Harness)'란 구체적으로 무엇을 의미합니까?

순수 언어모델 API 호출 앞뒤에서 시스템 프롬프트를 구성하고, 도구 실행 결과를 연결하며, 대화 히스토리와 중간 추론 상태를 유지·관리해 주는 소프트웨어 실행 프레임워크입니다.

Q2. 왜 표준 하네스에서는 62.7%에 불과했던 모델이 프로바이더 어댑터에서는 99.9%를 달성했습니까?

과제 해결 과정에서 발생한 실패 피드백을 효과적으로 요약하여 다음 턴의 프롬프트에 주입하고, 적절한 중간 연산 도구(샌드박스 등)를 최적화된 형태로 제공했기 때문입니다.

Q3. '상태(State) 연속성'이 깨지면 에이전트에 어떤 현상이 나타납니까?

방금 전에 실패했던 잘못된 파이썬 스크립트나 명령어를 다음 턴에서 똑같이 다시 시도하는 등 무한 루프에 빠지거나 작업 목표를 상실하게 됩니다.

Q4. '번들 어댑터(Bundled Adapter)'의 장점과 치명적 단점은 무엇입니까?

장점은 즉시 상용 수준의 고성능을 누릴 수 있다는 점이지만, 단점은 내부 로직이 블랙박스여서 벤더 종속성이 생기고 다른 모델로 쉽게 갈아탈 수 없다는 점입니다.

Q5. 엔지니어링 팀이 모델 벤치마크를 해석할 때 견지해야 할 원칙은 무엇입니까?

"모델 이름이 곧 성능이 아니다. 그 점수가 어떤 런타임 하네스와 도구 세팅 위에서 측정된 것인지(프로토콜)를 반드시 함께 확인해야 한다"는 원칙입니다.
